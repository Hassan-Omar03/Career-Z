# Parent complaint and child update follow-up

Latest scope correction: child updates are acknowledgement and reply/follow-up only. The complaint card no longer offers a meeting request, date/time/mode fields, or linked-meeting display, including for historical linked meetings. Parent-Teacher Meeting remains a separate feature with its existing external video meeting and saved history. No existing meeting records were deleted. The earlier descriptions below document the implementation history; the meeting controls described there are superseded by this correction. Updated isolated browser checks verify the absence of meeting controls while acknowledgement, replies, follow-up, resolution and separate PTM history still work; build passed.

## PTM child, class and recipient context

PTM records now retain course, class/section name, roll number and program alongside child, parent, teacher, school and subject. Both parties see these details and the same confirmed Join Meeting button. Requests select an actual teacher/subject/class context; the server rejects ambiguous multi-subject choices and fabricated assignments. Legacy meetings can display current verified context when unambiguous, while saved snapshots are retained for new meetings.

Recurring schedules now require a child and teaching context. The teacher sees the chosen child's class, roll, subject, school and linked guardians before creating the schedule. The schedule is advertised only to its target child's verified guardians, appears only in that child's available slots, and cannot be booked for another child. An availability rule does not have a join room until booked; booking creates a confirmed PTM and sends the exact generated external join URL plus child/class/parent/teacher/school/subject/time details to the parent. Teacher confirmation of an ad-hoc request also sends these complete details and the join URL. Manual link inputs remain absent from PTM confirmation and recurring creation.

Validation was extended to 41 backend tests, including cross-child recurring isolation, class/roll persistence, wrong-teacher rejection, exact subject selection and parent notification containing the identical join URL shown to both parties. The isolated browser check also exercised recurring child/context selection, guardian display, saved schedule context, absence of manual link input, and the confirmed Join Meeting link. Mobile screenshot ptm-recurring-context-mobile.png inspected. Build and targeted static checks passed. No real email or meeting was created by these tests.

Teacher updates now retain their reporting account, institution, child, verified course/timetable reference, and subject. The teacher picker preserves distinct child/subject combinations rather than collapsing a child's courses. Backend checks the actual teaching assignment and child's enrollment/class before accepting a subject. Earlier updates retain their original data and explicitly show when a subject was not recorded.

Parent dashboard cards show teacher/staff name and subject. Verified guardians can acknowledge once, append a reply/action taken, and request a meeting with the original reporting teacher. Replies put the update into awaiting_teacher; acknowledgment and meeting requests do not resolve it. Meeting requests retain an observation reference and its exact school/subject, use the existing PTM confirmation workflow, and appear on the update card with their current status. Each guardian's pending meeting affects only their own request control.

The reporting teacher's Parent-Teacher Meeting panel and authorized institution Parent Management reviewers see responses, follow-up history, and linked meetings. Reporting teachers/current school reviewers can add follow-up, resolve with an explanation, and reopen with a reason. Resolved records reject further replies until reopened. Events append to history with actor and timestamp; prior messages are retained.

Access is checked again at action time. Unrelated parents, unrelated teachers, unverified/revoked guardians, and ended school memberships cannot act on the complaint. Staff history reads require the reporting teacher's current relationship or school parents:manage authorization. Parent feeds and school notifications are limited to current verified school connections.

## Persistent PTM history

Both parent and teacher PTM panels now show the same meeting record, child/teacher/school, linked original child update, and Meeting history. Both panels refresh every 10 seconds and on browser focus. New status changes persist actor, timestamp, status, actual scheduled time, and no-show flag. The scheduler appends expiry events atomically. Existing older meetings show their saved status without fabricated earlier events. The dashboard's linked meeting uses confirmedDate after teacher confirmation/rescheduling.

The 39 backend tests passed again with explicit assertions that parent and teacher read the same linked confirmed meeting, that request and confirmation actors persist, and that cancellation appends history. Isolated browser checks also rendered the history on mobile without horizontal overflow; screenshot ptm-history-mobile.png was inspected. Production build passed.

Manual acceptance: teacher sends a discipline update for the child/subject; parent dashboard automatically displays it; parent acknowledges and replies; teacher sees the reply and adds follow-up; parent requests a future meeting and teacher confirms in existing PTM; teacher resolves with review notes; parent sees resolved status and preserved history. Reopen only when another follow-up is required.

Single-date PTM: teacher creation now selects a full date/time, exact child/class/subject and verified guardian. POST /ptm/schedule confirms immediately, reserves the teacher calendar, creates the existing automatic external room and notifies the selected parent with the same link and context. Successful submission closes the form; another meeting requires an explicit action. Failed submissions retain the draft. Historical recurring records remain preserved. Verified: 42 backend lifecycle/completion tests, isolated mobile browser form/routing/history checks, production build and targeted static checks passed. No live email or video call was executed.

PTM ambiguity fix: an explicitly selected enrollment course resolves to its own context rather than also matching timetable rows with different subject labels. Explicit timetable selection remains exact and its ID is persisted. Regression reproduces both paths; 43 lifecycle/completion tests pass. Submission errors retain the draft; successful submissions close it.

Native PTM correction: Jitsi URL generation has been removed. Parent and teacher Join Meeting buttons now open the existing CareerZLiveClassroom video component inline, using existing live-video Socket.IO signaling with a private ptm:<meetingId> namespace. REST RTC configuration and socket join/signaling/chat revalidate confirmed video status, exact meeting participants, teaching context and verified guardian connection. Existing TURN configuration is reused. Legacy confirmed PTM responses and notifications expose CareerZ dashboard links; dashboard deep links select the PTM tab. Classroom learning tools/poll creation are excluded from PTM.
