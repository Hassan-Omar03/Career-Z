## Institution, program aur admission foundation

Institution side par basic registration ko ek working operational lifecycle se connect kiya gaya. Institution owner apna institution register karta hai, verification documents submit karta hai aur Super Admin approval ke baad protected institutional actions use karta hai. Institution ke campuses, campus buildings, staff, teachers, students, parents aur class sections database records ke saath manage hote hain. Class section ke saath academic year aur class teacher assign kiya ja sakta hai. Institution staff ki access sirf staff membership dekh kar unrestricted nahi rehti; sensitive operations ke liye granular permissions enforce hoti hain. Fee confirmation, institution operations aur application approval jaise actions ke liye server-side permission checks lagaye gaye hain.

Academic program ko ab sirf application mein manually likha hua text nahi samjha jata. InstitutionProgram model aur uske APIs banaye gaye hain. Institution owner Admission Management mein program ka naam, department, class section, duration in terms, admission fee, total tuition, installments aur currency enter karta hai. Exam, hostel, transport, library aur activity charges ke liye institution Yes/No select karti hai. Yes select karne par amount bhi institution hi enter karti hai; No select karne par woh fee student ke plan ka hissa nahi banti. Platform kisi fee ka amount khud invent ya decide nahi karta. Woh institution ke entered rules ko validate, display aur later invoice records mein convert karta hai.

Student jab institution select karta hai to application form ab free-text program name accept nahi karta. Frontend institution ke active published programs load karta hai aur real dropdown dikhata hai. Program select karte hi student ko department, duration, assigned section, admission fee, complete tuition, installment count, approximate installment amount, enabled additional fees aur complete payable total application submit karne se pehle nazar aata hai. Backend bhi verify karta hai ke selected program us institution ka active program hai. Is tarah frontend manipulation se nonexistent ya unpublished program ke liye application submit nahi ki ja sakti.

Application submit hote waqt current fee plan ka snapshot application ke andar store hota hai. Is snapshot mein department, duration, admission fee, tuition, installments, currency aur enabled additional charges shamil hain. Iska purpose yeh hai ke institution future mein program price change kare to pehle se apply karne wale student ki agreed fee silently change na ho. Same institution aur same program ki duplicate active application ko bhi backend reject karta hai. Verified email ke baghair final application submission allowed nahi hai.

Admission flow mein online aur front-desk entries, submitted review, missing documents, waitlist, acceptance aur rejection states connected hain. Institution reusable online admission test create kar sakti hai, questions, options, correct answer, marks, passing percentage, instructions aur duration set kar sakti hai. Test applicant ko schedule aur assign hota hai. Student ke test payload mein correct answers expose nahi hote. Student attempt submit karta hai to backend automatic grading karta hai aur duplicate question indexes ko score inflate karne ke liye reuse nahi hone deta. External ya physical admission test ke liye schedule aur manual score entry bhi available hai.

Admission interview date aur time ke saath schedule hota hai. Mode in-person, video ya phone ho sakta hai. Video link, physical location, interviewer, notes aur recommendation store ki ja sakti hai. Assigned online test pass kiye baghair aur required interview complete kiye baghair applicant ko accept nahi kiya ja sakta. Accepted ya rejected application ko applicant dobara submitted state mein reset nahi kar sakta.

Final acceptance ab sirf status badge change nahi karti. Backend matching InstitutionProgram ko require karta hai, real institution membership record karta hai, StudentProfile ko program aur class section se link karta hai, admission letter verification code banata hai aur digital Student ID generate karta hai. Section ke published courses student ko automatically enroll kiye jate hain. Application ke stored fee snapshot se admission, tuition installments aur enabled additional-charge invoices generate hote hain. Institution ko har accepted student ka User ID copy karke tuition manually create nahi karni padti. Existing students ke liye bhi matching program setup ke baad section, course enrollment aur invoice backfill support add ki gayi hai.

## Student, teacher, parent aur institution ka academic relationship

Student profile ko institution ke saath ek single destructive link tak limited nahi rakha gaya. Multiple simultaneous institution memberships aur join/leave history record hoti hai. Primary institution, program aur class section student dashboard mein show hote hain. Transfer ya second enrollment pehli institution history ko overwrite nahi karta. Student digital ID, documents, learning history, goals, achievements, badges, portfolio, CV, applications, scholarships, jobs aur fees ko apne role workspace se manage karta hai.

Parent-child relationship consent-based banaya gaya. Parent request aur student approval ke baad linked child ka authorized data dekha ja sakta hai. Student ya authorized side link revoke/unlink kar sakti hai. Parent permissions granular hain; fee payment, health information aur other sensitive access separately controlled ho sakte hain. Parent attendance endpoint ko correct kiya gaya taa-ke ek child ka record mangne par poori class ke doosre students ka attendance expose na ho. Institution parent directory, guardian verification, feedback, PTM schedules, recurring meetings, minutes, actions aur escalations manage kar sakti hai. Parent AI Assistant sirf authorized child data ke context mein kaam karta hai.

Teacher profile mein qualifications, subjects, experience, bio, institution relationships aur independent-teacher setting maujood hai. Protected teaching actions se pehle verified teacher role check hota hai. Institution teacher directory se teacher discover karke employment offer bhej sakti hai. Offer accept hone se pehle teacher institution staff mein silently add nahi hota. Teacher offer accept ya decline karta hai; acceptance real employment record banati hai. Resignation aur termination dono employment history mein record hote hain. Independent teacher flow bhi consent based hai, aur minor student ke case mein guardian approval required hoti hai. Teacher ratings aur reputation records bhi implement kiye gaye hain.

## Courses, lessons aur student learning

Course creation teacher ownership ke saath linked hai. Institution course admission aur program assignment ke through milta hai. Completion hundred percent hone par enrollment completed state mein ja sakta hai. Published course ka full lesson content anonymous visitor ya unenrolled student ko expose hone wala security gap close kiya gaya. Assignments bhi sirf authorized teacher aur enrolled student contexts mein accessible hain.

It configured text aur voice providers se scenes aur narration prepare kar sakta hai, captions burn karta hai, browser mein ffmpeg.wasm se MP4 assemble karta hai, media storage par upload karta hai aur resulting URL ko course lesson ke saath save karta hai. ## Attendance workflow

Attendance ek single manual screen tak limited nahi rahi. Teacher enrolled class ke liye manual statuses record kar sakta hai. QR attendance mein teacher ek short-lived session start karta hai aur apni screen par QR display karta hai. Student apne device camera se teacher ka QR scan karta hai. QR random token aur readable session code ke saath expire hota hai, isliye old screenshot indefinitely reuse nahi ho sakta. Backend session validity, course enrollment aur duplicate check-in verify karta hai.

GPS attendance optional course location aur allowed radius use karti hai. Student browser location deta hai, backend configured latitude/longitude se distance calculate karta hai aur radius se bahar request reject karta hai. Face attendance ke liye student apna browser-computed 128-value descriptor enroll karta hai. Teacher ke browser ko sirf enrolled students ke required descriptor data milte hain, phir teacher live classroom camera se match karke real attendance record create karta hai. Remote student face request separately teacher approval queue mein jati hai; student ka self-reported match automatically attendance mark nahi karta. WebAuthn/passkey biometric verification interface bhi device-based attendance work ka hissa hai.

Attendance security mein unrelated user ko course attendance mein add karna, duplicate student record aur unauthorized course access reject hote hain. Parent ko sirf linked child ka scoped attendance milta hai. Attendance document method, checked-in time, session/location information aur marker retain karta hai. QR, GPS aur face se create hone wale records mein institution, course aur class section linkage correct ki gayi.

## Wallet, payments, ledger, commission, escrow aur refunds

User wallet balance, transaction history, Paddle top-up, internal transfer aur withdrawal request use kar sakta hai. Admin pending withdrawals review karta hai. Fee records gross amount, platform commission, gateway charges, configured tax, net amount, payment method, provider reference, receipt number, refund state aur escrow state store kar sakte hain. Institution manual verified payment confirm karti hai, unique receipt create hoti hai aur amount held escrow state mein ja sakta hai.
